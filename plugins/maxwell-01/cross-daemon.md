Cross-daemon lets agents on one Paseo daemon list workspaces and agents, read recent agent activity, send prompts, and start and archive agents on other daemons. Every participating daemon needs this plugin and Paseo 0.9.2 or newer. Open Settings → Plugins → cross-daemon → Settings to switch participating daemons on. “This daemon” controls the current host and “All daemons” lists connected hosts; switches are off by default.

Each switched-on daemon shares its relay pairing link with the other switched-on daemons through the connected app. A pairing link grants full control of its daemon. Agents on participating daemons can read activity and send prompts, including content handled by the receiving agent's selected provider. Only switch on daemons you want to give each other that reach. Links, queued messages, completion watches and records of agents started by the plugin are stored on each daemon with owner-only permissions. These permissions do not exclude that daemon's own agents, which run as the same user. Tools do not print pairing links.

The app syncs peer lists while open, including after switch changes and every minute. Daemons retain their last lists when it closes; an unresponsive daemon stays on peers' lists until it answers switched off. Switching a daemon off clears its own list immediately, and other daemons remove it on their next successful sync.

New Claude, Codex and OpenCode agents receive the cross-daemon MCP tools. Claude and Codex tools are pre-approved and run without another permission prompt; OpenCode tools are not pre-approved. Existing agents retain the tools they were created with. Codex does not pass the caller agent ID to the MCP process, so its messages have no agent reply target or finish notice.

Starting an agent uses an absolute folder on the destination daemon and reuses that folder's workspace or creates a local workspace. The default permission mode is `auto`; callers can select another mode and provider. First prompts travel on the CLI command line and are visible to other users who can inspect processes on the calling machine. The plugin invokes the installed Paseo CLI and writes its local MCP proxy; it does not download software.

Archiving is limited to idle agents recorded as started through this plugin on the calling daemon. It also tries to archive a workspace it created, which closes that workspace's agents and terminals. Cleanup keeps the workspace when another listed agent has the same folder or the agent list reaches 200 entries. This check uses folders rather than workspace membership: an agent placed in that workspace with a different folder would be archived with it.

Messages to idle agents are sent immediately; messages to busy agents are queued in plugin storage and retried every 15 seconds once idle. The queue survives restarts, has a 20-message limit per agent and drops messages after 24 hours. A timeout or restart during delivery is not automatically retried because delivery may already have happened. A target that starts work between the status check and delivery can still be interrupted. Requested completion notices return the destination agent's last message to the caller after the caller becomes idle.
